1. Summary

A local Flask and Socket.IO web app for Windows. It listens to a live call on two audio channels (your microphone and the computer's speaker output), transcribes both with Azure AI Speech, and sends the recent conversation to a Claude model on Azure AI Foundry. The model fills a form with the property address, any number of parcels, any number of taxing agencies per parcel, and any number of tax installments per agency. Repeats, read-backs and confirmations on the call are recognised so they never create duplicates or overwrite stored values. Values appear in the browser as the call goes on, you can correct them, and the finished call is saved to a local SQLite database and exportable to Excel.

Verified: 14 unit tests pass; the agency form was clicked through in a real browser (add, delete, save, export, no JavaScript errors); the Flask and Socket.IO wiring was exercised end to end with a stubbed LLM (before the agency level was added; not re-run since); real calls to your Claude deployment extracted the property, parcel, two agencies and their installments correctly, and a six-turn call full of read-backs and one correction ended with exactly one parcel, one agency and one installment, saved and exported to Excel; the Speech key authenticates in centralindia; Export Excel works with an empty and a populated database; Start with no microphone shows a banner on the page.
Not verified: live transcription with real audio. This machine has no microphone available (the session uses "Remote Audio", which indicates Remote Desktop) so the mic path and the full speak-to-form loop have not been run by me. The loopback (system audio) device is present.

Everything runs in one Python process. Each browser connection gets its own Session object holding its transcript, extracted state, locked fields and deleted items. Three background threads run per recording: audio/mic recognizer, speaker (loopback) capture plus its recognizer, and the extraction worker. The app listens on 127.0.0.1:5000 only.

The property address vs parcel address distinction follows the table you supplied: the property address is the raw input as given by the caller (unstandardised, possibly a mailing address); the parcel address is the canonical situs address recorded by the county for a specific parcel.

How to add or change a field

  1. Add a dict to PROPERTY_FIELDS, PARCEL_FIELDS, AGENCY_FIELDS or INSTALLMENT_FIELDS in fields.py with key, label, type (string, amount or date) and hint (the instruction shown to the model).
  2. Restart the app. The prompt, tool schema, web form, database columns (added with ALTER TABLE on first connect) and Excel export columns all pick it up. No other file needs editing.
  3. To add a new level (for example owners per parcel; the agency level was added this way), more code is needed in extractor.py (schema, merge) and ui.py.

6. Runtime flow

Page load

  1. Browser opens / and loads the HTML plus Socket.IO 4.7.5 from cdnjs.
  2. On connect the server creates a Session, sends config (the four field lists) and state_update (empty state).
  3. The browser builds the Property section and renders parcel cards, each with its agencies and installments, from state.

Start

  1. If AZURE_SPEECH_KEY is empty: emit error_message and stop.
  2. Reset the session (new call id, empty transcript, state, locks and deletions). Any manual edits made before Start are discarded.
  3. Start three threads: extract_worker, mic_worker (Caller-1) and speaker_worker (Caller-2).

During the call

  1. Each channel's recognizer emits partial results (shown as "listening...") and final results.
  2. A final result is dropped if it looks like an echo of the other channel (section 11); otherwise it is appended to the session log and sent to the page as new_message.
  3. The new final result sets a "dirty" flag. The extraction worker sees it, waits 2 seconds (so a speaker can finish), then runs a live extraction on the last 12 utterances plus the current values.
  4. The model first writes a short reasoning (new items, repeats ignored, corrections), which is printed in the terminal. Its answer is then merged into the session state under the repeat-safe rules in section 9.
  5. If the merge changed anything, state_update goes to the browser and the form updates without overwriting the field you are typing in.

Stop

  1. Stop flag set, recognizers stopped, 0.3 s pause so in-flight results land.
  2. One final extraction over the whole transcript (blocks the Stop handler until the model answers).
  3. The call is saved to SQLite (upsert by call id) and the page is told recording_stopped and saved.

Save call, Clear, Export

  • Save call upserts the current state and transcript under the same call id, so clicking it repeatedly never creates duplicates.
  • Clear resets the session (new call id) and clears the form and transcript. It does not delete anything already saved.
  • Export Excel opens /export.xlsx in a new tab and downloads calls.xlsx built from all saved calls.
  • If the browser disconnects, the session and its audio are stopped. Unsaved data is not saved automatically.

9. Extraction rules

What the model is told

  • Extract property tax details from a live call; a property can have several parcels, each parcel several taxing agencies, each agency several installments.
  • Use only what is explicitly said; empty string for anything not stated; never guess.
  • Return every parcel, agency and installment already in CURRENT STATE with its id and its values unchanged, and add new ones with an empty id.
  • Do not move a value between parcels, agencies or installments unless the speaker clearly does.
  • Repeats and confirmations: a read-back ("so that is parcel 123-456-789, correct?", "yes, 1,250 due April 10") of something already stored is not new information. Do not create another parcel, agency or installment and do not change the stored value. A re-spelled or re-formatted version of the same value is a repeat.
  • Never blank or drop anything already in CURRENT STATE.
  • Additions: if a repeat adds a new detail (the agency's phone is now given), return the stored text plus the new detail; never less than what is stored.
  • Corrections: only when a speaker explicitly says an earlier value was wrong ("no, it is 456 not 457", "actually the due date is May 1"), add an entry to corrections with the item id, field key, new value and the quote as evidence. Use id property for property fields. A mishearing or unclear different value is not a correction.
  • Review first: before the data, write a brief reasoning: what is new, which repeats or confirmations were ignored, which corrections were made. This is the "LLM reasons and reviews" step; it is logged in the terminal as [extract] ... and is not stored.
  • Followed by each field's hint text.

The model must answer through a single tool, record_extraction, whose input schema is generated from fields.py. This keeps the response machine-readable. The app does not rely on strict schema enforcement here, so the merge step tolerates missing or odd values.

Merge rules (merge())

The prompt asks the model to behave; the merge enforces the same integrity on its own, so a model slip cannot damage stored data.

RuleBehaviour
Stored values are not rewrittenA repeat never replaces a stored value. Amounts and dates are only filled when empty. Text values (addresses, names, notes, agency details) are filled when empty, or replaced only by a longer version that contains the stored text (the address "9 Elm" becomes "9 Elm Rd"; a shorter or different one is ignored).
Empty never clearsAn empty or missing value from the model never erases a field you already have.
Explicit correctionsThe only way a stored value is replaced. Listed in corrections with the item id, key and quote; the new value is normalised first. Unknown ids and keys are ignored.
Locked fieldsAny field the user edited is stored as (item id, key) and is never changed by the model, including by a correction.
Parcel matchingBy id returned by the model; otherwise by normalised parcel number (lower-case letters and digits only, so 111-222 equals 111222). No match creates a new parcel, but only if it has at least one value.
Agency matchingWithin a parcel: by id; otherwise by name, equal after normalising or one containing the other (at least 4 characters). No match creates a new agency.
Installment matchingWithin an agency: by id; otherwise same due date; otherwise same amount when either side has no date (so a date heard later completes the existing installment instead of adding one). No match creates a new installment.
Deleted stays deletedA deleted parcel (by normalised number), agency (by parcel and normalised name) or installment (by agency id, amount, due date) is not re-added by later extractions.
NormalisationEvery value goes through normalize() before it is compared or stored.
Changes reportedmerge() returns whether anything changed so the browser is only updated when needed.

10. Storage

SQLite file data/calls.db. Created automatically; columns for new fields are added automatically. A database created before the agency level (installments tied to parcels) is not compatible: delete it or set DB_PATH to a new file. The old one in this folder was deleted.

TableColumns
callscall_id (primary key), saved_at, transcript, plus one column per property field
parcelscall_id, parcel_id, plus one column per parcel field
agenciescall_id, parcel_id, agency_id, plus one column per agency field
installmentscall_id, agency_id, installment_id, plus one column per installment field

All field columns are TEXT. save_call is an upsert: it deletes the call's old rows and re-inserts them in one transaction, so saving repeatedly is safe.

Excel export

One row per installment, with agency, parcel and property values repeated, in this column order: Call ID, Saved At, Property Address, Parcel Number, Parcel Address, Agency Name, Agency Details, Tax Amount, Tax Due Date, Installment Note. A parcel with no agencies, an agency with no installments, or a call with no parcels still produces one row with blanks. Rows are ordered by save time. The export covers every saved call, not only the current one.

The transcript is stored with timestamps and speaker labels, unredacted.

11. Audio capture and speech

ItemDetail
Caller-1Default Windows microphone, handled directly by the Speech SDK (use_default_microphone=True).
Caller-2WASAPI loopback of the default speakers using PyAudioWPatch, so the remote party's voice is captured without "Stereo Mix". Format follows the device (sample rate and channel count) and is pushed to a Speech PushAudioInputStream. Needs Windows.
Speech settingsLanguage en-US (configurable). End-of-speech silence 1200 ms and initial silence 15000 ms, to reduce cut-off sentences.
Auto-restartIf Azure cancels or ends a session while still recording, the recognizer is rebuilt, up to 5 times per channel, 1 s apart.
Echo filterA final utterance is dropped if, within 2.5 s, the other channel produced text at least 72% similar (SequenceMatcher). It guards against your mic picking up the call audio. It is heuristic: very short repeated replies such as "yes" can occasionally be dropped.
Speaker labels"Caller-1" and "Caller-2" mean mic and system audio, not identified people. There is no diarization within a channel.
Thread layoutPer recording: extraction thread, mic recognizer thread, speaker capture thread, plus a recognizer thread for Caller-2.

17. Known gaps and limitations

  • Speech path not live-tested. No microphone is available in this session, so the end-to-end spoken run is still to be done on a machine with a mic and call audio.
  • No evidence or confidence per field. The earlier design suggested storing the quoted source sentence and a confidence score for each value. Not built; reviewers cannot yet see why a value was extracted.
  • Model output is not schema-enforced. A forced tool call is reliable but not guaranteed; malformed answers are ignored by the merge or surface as warnings.
  • Wrong first values stick. Because repeats never overwrite, a value the model first heard wrongly is only fixed by an explicit spoken correction (which the model must recognise) or by you editing the field. A later, better-sounding repeat is deliberately ignored; text values can only be replaced by a longer version of themselves.
  • Reasoning is not stored. The model's repeat/correction review is only logged in the terminal, not shown on the page or saved to Excel.
  • Agency details are free text. Phone, address and website are in one field, so they cannot be filtered separately in Excel.
  • Installment and agency identity are heuristic. Installments match by id, due date, then amount; two installments with the same date under one agency could merge. Agencies match by name containment, so very similar names (for example "County" and "County Library District") could merge.
  • Deleted-installment memory depends on values. If the model later returns it with a different amount or date it can reappear. A deleted agency without a name is not remembered.
  • Stop blocks while the final extraction runs. A slow model call delays the "saved" confirmation.
  • Failed LLM calls are silent in the UI. Only the terminal shows "extraction failed".
  • Transcriber is not a separate module. Swapping to Deepgram or AssemblyAI means editing app.py; the planned adapter seam and vendor bake-off are not done.
  • Speaker identification. Mic vs system audio only; several remote people are not separated.
  • Echo filter is heuristic. May drop short repeated replies.
  • Data handling. Transcripts stored unredacted; no delete-call or retention feature; no login.
  • Export is all-or-nothing. It always exports every saved call.
  • Typed values are cleaned on blur only. A value is normalised when you leave the field, so it is raw while you type and in the saved state until then.
  • Start discards pre-Start edits. Reset on Start clears anything typed before recording begins.
  • Windows only. Loopback capture relies on WASAPI.
  • Housekeeping. .env.example is missing; .env - bak and legacy/ hold old credentials; .deployment and .vscode App Service settings are obsolete; .env may contain variables from another project that this app ignores.
